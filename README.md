# Schedule Bot

Телеграм-бот для еженедельного расписания: добавляешь занятие один раз (с днями недели), бот сам показывает его каждую неделю, присылает напоминания и выгружает красивый PDF-календарь. Интерфейс бота на английском, дни понимает и на английском, и на русском.

## Как устроено

- **Шаблон** (`/template`) — то, что повторяется каждую неделю: уроки, работа, спорт. Заполняешь один раз.
- **План** — конкретные дела с датами на ближайшие 7 дней. Бот сам создаёт их из шаблона и каждую полночь добавляет новый день. Разовые дела добавляются в план через `/add`.
- `/del 3` убирает только это конкретное дело. Если оно из шаблона, бот запоминает пропуск, а через неделю оно появится снова. Чтобы убрать совсем — `/template del T1`.
- Номера плана (`#3`) и шаблона (`T1`) свои у каждого пользователя; освободившийся номер занимает следующее новое дело.

## Команды

Шаблон (каждую неделю):
- `/template` — показать шаблон
- `/template add ДНИ ВРЕМЯ Название` — например `/template add monday wednesday 10:00-11:30 Math`. Без дней — каждый день
- `/template edit T1 ДНИ ВРЕМЯ Название` — изменить; ближайшие дела в плане пересоздаются, пропуски сохраняются
- `/template del T1` — убрать из шаблона вместе с будущими делами из плана
- `/template remind T1 15` — напоминание для всех недель (`0` — в момент начала, `off` — без напоминания)

План (ближайшие 7 дней):
- `/add ДНИ ВРЕМЯ Название` — разовое дело, например `/add friday 15:00 Dentist`, `/add tomorrow 19:00-21:00 Cinema`. Без дней — сегодня
- `/today` — план на сегодня
- `/week` (или `/list`) — план на 7 дней начиная с сегодня, с номерами
- `/pdf week` — PDF-календарь с сегодняшнего дня на 7 дней вперёд; `/pdf day`, `/pdf tomorrow`, `/pdf friday` — на один день
- `/del 3` — убрать дело #3 (можно несколько: `/del 3 5`)
- `/remind 3 15` — напоминание только для этого дела (по умолчанию 10 минут, максимум 1440)
- `/help` — справка

Форматы:
- Дни: `monday … sunday` или `понедельник … воскресенье`, диапазон `monday-friday`, `weekdays` / `weekend` / `daily`, для `/add` ещё `today` / `tomorrow`. Сокращения (`mon`, `пн`) тоже понимаются.
- Время: `10:00-12:00` (можно `9:30-10`, `10-12`) или просто `8:00`.
- Если новое дело пересекается с другим, бот предупредит, а в PDF они встанут рядом.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Что это |
|---|---|---|---|
| `BOT_TOKEN` | да | — | токен от @BotFather |
| `TIMEZONE` | нет | `Asia/Almaty` | часовой пояс расписания |
| `DB_PATH` | нет | `<RAILWAY_VOLUME_MOUNT_PATH>/schedule.db`, локально `./schedule.db` | путь к SQLite-базе |
| `DEFAULT_REMINDER_MIN` | нет | `10` | напоминание по умолчанию, мин |

Если к сервису на Railway подключён Volume, база автоматически кладётся в него — `DB_PATH` задавать не нужно.

## 1. Создать бота в Telegram

1. Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → имя → username (должен заканчиваться на `bot`).
2. Получишь токен вида `123456789:AAH...`. Это пароль от бота — никуда не коммить. Если утёк: @BotFather → `/revoke`.

## 2. Локальный запуск (проверка)

```bash
python -m venv venv
source venv/bin/activate            # Windows: venv\Scripts\activate
pip install -r requirements.txt
export BOT_TOKEN=твой_токен         # Windows (PowerShell): $env:BOT_TOKEN="твой_токен"
python bot.py
```

Остановить — `Ctrl+C`. **Перед запуском на Railway локальный бот должен быть остановлен**, иначе будет ошибка `Conflict: terminated by other getUpdates request`.

## 3. Деплой на Railway

1. Залей папку в приватный репозиторий GitHub.
2. [railway.com](https://railway.com) → войти через GitHub → New Project → Deploy from GitHub repo → выбрать репозиторий.
3. Первый деплой упадёт с `BOT_TOKEN не задан` — это нормально.
4. Сервис → Variables → добавить `BOT_TOKEN`.
5. Volume: правый клик по пустому месту на канвасе проекта (или `Ctrl/⌘+K` → Volume) → выбрать сервис бота → Mount path `/data`.
6. Нажать Deploy / Apply changes.
7. Domain генерировать не нужно — это worker, а не сайт.
8. В логах деплоя должно быть:
   ```
   Bot starting (timezone=Asia/Almaty, local time 2026-09-23 18:40, db=/data/schedule.db)...
   Planned 0 upcoming events
   ```
   Проверь, что `local time` совпадает с твоими часами, а `db` начинается с `/data/`.

Обновление: `git push` → Railway сам пересоберёт и перезапустит бота. Данные в Volume сохраняются.

## Частые проблемы

- `Conflict: terminated by other getUpdates request` — бот запущен в двух местах (скорее всего, локально и на Railway). Останови локальный.
- `BOT_TOKEN не задан` — не добавлена переменная или не нажат Deploy после добавления.
- `Volume не подключён — база ... будет стираться` в логах — не подключён Volume (шаг 5).
- Бот молчит — смотри Deploy Logs на Railway, статус сервиса должен быть Active.

## Имя и аватарка бота

Всё делается в [@BotFather](https://t.me/BotFather), код трогать не нужно:

- `/setname` — отображаемое имя (оно же попадает в подвал PDF)
- `/setuserpic` — аватарка (квадратная картинка, лучше от 512×512)
- `/setdescription` — текст на пустом экране до нажатия Start
- `/setabouttext` — короткое описание в профиле бота

Username (`@..._bot`) у бота поменять нельзя — только создать нового через `/newbot` и заменить `BOT_TOKEN` на Railway. Данные при этом сохранятся (в личке chat_id = id пользователя), но всем придётся нажать Start у нового бота.
